# Research audit: comparator semantics (2026-10-28)

Scope: the technical PGSO paper (Juan Carlos), not Sami or a commercial study.
Source inspected: 06e2432d11898feca4f34a6c5baa494445fa48e7.

`public_voice/pilot.py::_instantaneous_blocks` uses an existential test over every
observation supplied for an utterance. A high observation followed by a nominal
observation still returns true. It also defaults a missing confidence field to
1.0 and accepts positive infinity as a high value. These are characterized facts
about this function, not evidence that malformed inputs occurred in prior runs.
They do not identify a bypass in the Rust authorization runtime.

Call the historical comparator **T_any-window**, not a last-window comparator.
Do not silently rewrite the archived results. A new T_last-accepted comparator
needs its own protocol/configuration identity, numeric precision, validation,
low-confidence hold and host-expiry semantics. Such a comparator still has state
for holding/expiry, even without hysteresis. It is not a purely stateless arm.

Run the dependency-free source characterization:

```bash
python3 experiments/reproducibility/audit_threshold_semantics.py \
  --output /tmp/pgso-threshold-characterization.json
```

The test compiles only the named function and its literal confidence constant;
it does not import the pilot, create agents, run providers or download models.
The output records the actual source hash and checkout commit. Six characterization
checks passing means that the historical behavior was reproduced, not that the
behavior is the desired new experimental contract.

No production runtime, historical evidence or manuscript is changed by this PR.
A separate local audit package contains candidate baseline and ledger-validation
tests; they are not claimed here as integrated Rust or real-agent validation.
